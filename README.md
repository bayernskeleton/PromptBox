<p align="center"><strong>面向 Prompt 优化的本地工作台</strong></p>

<p align="center">
  选择已有 Prompt → 可选补充信息 → 一键优化 → 诊断与修改报告 → 可选实际输出对比 → 人工采纳 → 版本回溯 / 快捷调用 / 跨端迁移
</p>

PromptBox 是一个针对 Prompt 的本地优化工作。用户先选择已有 Prompt；如果需要，可以在一键优化前展开补充信息，输入业务上下文、失败输出、触发输入或优化目标。系统依托提示词诊断与重构 Agent 生成候选版本，并输出诊断和修改报告。候选生成后，用户还可以让原 Prompt 与候选 Prompt 结合同一份业务上下文和同一个测试任务分别生成实际输出，再进行人工比较、采纳和版本回溯；同时支持快捷调用和跨端迁移。

## 当前能力

- Prompt 片段、分类、标签、版本与变体管理
- 全局快捷键、剪贴板复制和 Markdown 编辑工具栏
- 一键优化：提示词诊断、重构 Agent、候选 Prompt 生成与诊断/修改报告；业务上下文、失败输出、触发输入和优化目标均为优化前可选补充材料
- 基线版 / 候选版 1–5 条验证样本的并排验证与逐样本人工裁决
- 验证样本来源声明、用户确认、上下文快照、截断状态与只读证据回看
- 本地单文件上下文加载、字符量提示与截断标记；超过约 80,000 字符时必须选择截断发送或取消
- 多文件/文件夹上下文自动组装：文件夹递归扫描、多选文件、本地确定性解析排序与 Context Pack 组装；默认排除依赖/缓存/构建产物，500 文件、100 MB 总量、10 MB 单文件的本地保护线
- Prompt 变量说明、示例值、集中填写和自动快照
- 独立的验证记录浏览、筛选和只读详情
- V3 快捷调用：Quick Copy Palette 搜索、当前/历史版本选择、变量填写、复制后自动收起和无打扰调用记录
- V4 Markdown 资产包：按分类批量导出（可选 ZIP）、导入预览、冲突分类和用户确认写回
- 本地 JSON 存储与原子写入

> 多文件上下文组装已完成代码实现、自动化测试、真实 GUI Smoke 与 cafe/cyber 主题点验；V3 已通过真实桌面 GUI 点验；V4 待具备 Tkinter 的打包环境复核 EXE 启动。

模型生成的候选只是草稿。用户可以直接查看诊断和修改报告，也可以在优化前提供业务上下文，让候选更贴近真实场景。候选生成后，如需验证，用户必须提供测试任务；系统让原 Prompt 与候选 Prompt 结合同一份业务上下文和同一个测试任务分别生成实际输出，再由用户比较结果。只有用户完成人工采纳，候选才会进入版本留存流程；PromptBox 不自动宣布候选版本胜出。

## 核心工作流

```text
选择已有 Prompt
    ↓
可选：展开“补充信息”，填写业务上下文、失败输出、触发输入或优化目标
    ↓
一键优化
    ↓
提示词诊断与重构 Agent 生成候选
    ↓
查看诊断报告、修改报告和候选 Prompt
    ↓
可选：填写测试任务，沿用或调整业务上下文
    ↓
原 Prompt + 同一业务上下文 + 同一测试任务 → 原版实际输出
候选 Prompt + 同一业务上下文 + 同一测试任务 → 候选实际输出
    ↓
人工比较、采纳或保留原版本
    ↓
保存版本记录与验证证据
```

一次验证可保存 1–5 条样本。每条样本记录来源类型、来源标签、用户确认、上下文快照、双侧输出和人工裁决；已验证版本可从版本历史进入只读证据回看。

### 证据边界

- `real_business_replay`、`historical_failure`、`designed_boundary`：由用户提供或确认的业务回放、历史失败输入或人工设计边界样本。
- `ai_synthetic`：仅用于探索、界面调试或回归测试，**不能单独作为正式采纳证据**。
- `user_confirmed=true` 仅表示用户声明来源，系统不会也无法从文本本身认证材料的客观真实性。
- 系统记录原始上下文字符数、实际发送字符数、SHA-256 快照哈希和截断状态。多文件组装的默认过滤和本地保护线不等于模型上下文容量；模型容量未知时允许发送，只提示字符数和 token 估算。当前不提供 RAG 或自动项目上下文检索。
- 旧记录缺少来源或快照字段时，回看界面只会明确提示缺失，不会伪造补齐。

## V3 / V4

### V3：快捷调用

V3 提供 Quick Copy Palette：按快捷键唤起小型检索面板，搜索标题、标签、分类和正文，默认调用当前版本，需要时主动展开历史版本，填写变量，复制最终文本后自动收起并留下一条无打扰调用记录。它不以“稳定版”作为调用门槛，也不负责长文本编辑、修复或验证。

### V4：Markdown 资产包

V4 把 Prompt 导出为按分类整理的 Markdown 文件。文件正文可脱离 PromptBox 阅读，导入时先展示新增、更新、重名和格式错误，用户确认后才写回。本地资产仍是唯一可写来源；不做后台双向同步和静默覆盖。

## 界面预览

仓库公开前应补充真实、脱敏的运行截图。建议至少包含：

1. 一键优化工作台：从已有 Prompt 出发，可展开补充信息后生成候选，并展示诊断与修改报告；
2. 并排验证器：让原 Prompt 与候选 Prompt 结合同一业务上下文和同一测试任务生成实际输出，再查看两份结果；
3. 证据回看：从版本历史查看只读的来源、快照与人工裁决。

不要上传真实业务上下文、内部 Prompt、模型响应或 API Key。

## Quick Start

### 环境

- Windows
- Python 3.10+
- Tkinter（通常随 Windows Python 安装包提供）

### 安装依赖

```bash
python -m venv .venv
.venv\\Scripts\\python.exe -m pip install -r requirements.txt
```

### 启动

```bash
.venv\\Scripts\\python.exe promptbox_launcher.py
```

也可以直接运行：

```bash
.venv\\Scripts\\python.exe promptbox.py
```

### 运行测试

```bash
.venv\\Scripts\\python.exe -m pytest tests/
```

公开发布前应在隔离环境复跑测试，并以当次实际结果为准。README 不预先承诺固定测试数量。

## 启用模型辅助修复与验证

未配置模型服务时，PromptBox 的本地管理、速检和界面仍可使用；候选生成与真实载荷验证会提示缺少配置。

设置环境变量：

```text
PROMPTBOX_REPAIR_API_BASE=https://<OpenAI-compatible endpoint>/v1
PROMPTBOX_REPAIR_API_KEY=<your API key>
PROMPTBOX_REPAIR_MODEL=<model name>
```

服务需要提供兼容 OpenAI `POST /chat/completions` 的接口。只有用户主动请求候选生成或真实验证时，相关 Prompt、上下文和任务输入才会发送到所配置的服务。**本地存储优先不等于数据绝不离开设备。**

## 数据位置

默认数据保存于：

```text
~/.promptbox/snippets.json
```

演示或 GUI 检查时，可设置独立目录：

```text
PROMPTBOX_DATA_DIR=<isolated data directory>
PROMPTBOX_DEMO=1
```

本地 JSON 使用临时文件替换降低写入中断风险，但不提供哈希、签名或 append-only 审计能力；不要将其描述为不可篡改日志。

## 技术取舍

| 选择 | 原因 |
|---|---|
| Tkinter 原生界面 | 先验证个人工作流，避免为原型引入 WebView / Electron 运行时。 |
| 人工成对裁决 | 让业务使用者保留最终验收权，不用模型自动打分替代真实判断。 |
| 本地 JSON 单一写入点 | 降低多文件同步冲突，保持版本与案例关系可回看。 |
| Markdown 编辑工具栏与资产包 | 降低 Prompt 编写成本；V4 负责导出、导入预览和冲突提示。 |

## 当前限制

- 验证样本不是系统自动认定的“真实业务”。系统只保存用户的来源声明、确认状态和运行快照。
- AI 合成样本不能单独用于正式采纳；它只能服务于探索、界面调试和回归测试。
- 当前单文件上下文仍使用约 20,000 / 80,000 字符提示与确认；多文件功能的 500 文件、100 MB 总量、10 MB 单文件是本地扫描/解析保护线，不是模型上下文限制。
- 不提供自动“候选更优”判定。
- 不提供多模型横向比较。
- 多文件轻量解析支持 PDF/DOCX/XLSX/PPTX 的文本提取，不包含 OCR、复杂版式还原或旧版 `.doc/.xls/.ppt` 原生解析。
- 当前面向 Windows 桌面使用；尚未宣称跨平台验证。
